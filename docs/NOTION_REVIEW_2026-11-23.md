> 아래는 최초 재검토 기록이다. 이후 공공데이터·69개 API 실제 요청/응답·로컬 PDF/ERD까지
> 확대한 최신 결과는 [후속 검토](FULL_REVIEW_2026-11-23.md)를 따른다.
> 수납 처방전 약품명 누락과 V2 이전 시드는 후속 작업에서 수정했다.

검토일: 2026-11-23. 기준 코드: BE `2d5b7fe` 및 현재 로컬 FE.
사용자가 개인 스페이스에 복제한 [팀 홈](https://app.notion.com/p/6d5938594612832f95f50136ba8010ab)을 조회했다.
복제 후 편집 시각은 원본 문서의 최신 합의 시각을 증명하지 않는다.
원본과 복제본의 완전 동일성까지 검증한 결과는 아니다.

## 문서와 구현의 차이

| 항목 | Notion / 로컬 문서 | 현행 구현과 판단 |
| --- | --- | --- |
| DBMS | API 정리본과 11/9 회의는 PostgreSQL을 명시 | 이미 PostgreSQL 기반. 새 DBMS로 전환하는 작업은 불필요 |
| 진찰료 | 업무분석서·로컬 업무분석서는 금액 하나로 설명 | 11/9 회의·API 상세·코드는 초진 18,000원 / 재진 15,000원. 유형별 이력을 시드에 반영 |
| 의사 프로필 | API 정리본·의사 등록 명세는 DOCTOR의 staff 행과 표시명 동기화를 설명 | V2가 의사의 staff 중복 행을 제거. 현재 코드는 doctor 이름을 사용하며 의사 등록에서 계정을 함께 만들 수 있음. 기존 accountId 연결도 지원 |
| 수행자 FK | 진찰료 명세 등 일부는 관리자 staff_id를 설명 | V2의 `set_by_account_id`, `checked_in_by_account_id`, `processed_by_account_id` 사용 |
| 로컬 테스트 시드 | FE `dev/local-test-seed.sql` 사용 | V2 이전 컬럼 `set_by_staff_id`와 의사 staff 행을 사용. 현재 스키마에 그대로 적용할 수 없음 |
| 설정 파일 | Notion은 application.yml / application-local.yml 예시 | 저장소는 application.properties와 테스트 properties를 공유. YAML은 Git·빌드에서 제외됨 |
| 약품명 | 11/15 회의는 약품 ID 응답에 medicationName 추가 결정 | 담당 진료 상세와 DUR 응답은 반영. 수납 처방전 조회는 prescription_item만 조회해 약품명이 없음. FE는 `약품 #ID`로 대체 표시 |

| Figma | 팀 홈은 L4sXICdHuz6afEqibSiKpG, 이전 공유 링크는 tQHNMcxzAbDA8eRMuLiih3 | 파일 키가 다름. 같은 파일로 가정하지 않음. 화면·ERD 등 파일별 용도와 최신성은 미확정 |

의사 분리는 11/15 회의에 중복 검토 항목으로 남아 있고 코드 V2에는 이미 적용됐다.
따라서 시드는 코드의 현재 스키마를 기준으로 생성하되, Notion API 문구도 이후 정리해야 한다.
기존 API 계약의 모든 차이를 이번 작업에서 자동 변경하지 않았다.

## 더미 데이터의 출처

11/15 회의록은 BE 담당 시드에 로그인 계정·진료과·의사 일정·진찰료가 없어
FE의 `dev/local-test-seed.sql`을 사용해 로그인하고 있다고 명시한다.
이는 해당 SQL의 사용 기록이며, 누가 어느 서버에서 실행했는지까지 증명하지 않는다.

BE의 `R__seed_medicine.sql`은 약품·병용금기·연령금기의 기준 데이터다.
빈 PostgreSQL 18에 Flyway를 적용했을 때 약품 194개, 사용자 계정 0개였다.
테스트 전용 `IntegrationSupport`가 만드는 계정·예약은 별도 테스트 데이터이며
그 코드가 운영 DB를 자동 채우는 경로는 아니다. 연결 설정을 바꾸면 대상 DB는 달라질 수 있다.

실제 온케어의 `/demo-api/seed` 구현은 현재 BE·FE 소스에서 발견되지 않았다.
서버 시연 초기화 기능은 별도 구현으로 관리되는 것으로 보이나 배포 파일·서버 로그는 확인하지 않았다.

## 새 PostgreSQL 시연 시드

`dev/generate_demo_seed.py`와 [시연 데이터 안내](DEMO_DATA.md)를 추가했다.
현재 V2 스키마와 위 회의의 업무시간·요금·가상 데이터 원칙을 사용한다.
기존 공공 약품·금기 기준을 참조하며 이를 임의의 가짜 약품으로 대체하지 않는다.

임시 PostgreSQL 18에서 확인한 초기 구성은 계정 8개, 직원 3명, 의사 2명,
환자 3명, 예약 8건, 진료 5건, 처방 4건, 결제 2건, 금기 예외 2건이다.
로그인 8개와 역할 프로필, 초진·재진 금액, 대기열, 접수, 병용·연령 경고를 실제 API로 확인했다.
반복 실행 거절과 데이터 보존도 확인했다. 기존 서버·Render DB에는 적용하지 않았다.

## 확인하지 못한 범위

- 11/15 회의의 테이블 정의서 XLSX와 ERD PNG는 다운로드 URL 발급 후에도 HTTP 404였다.
  첨부물의 내부 내용과 현행 DDL 전체가 일치한다고 판단하지 않았다.
- Figma 디자인 본문, 현재 온케어 서버의 배포 파일·실행 커밋, 서버 시드 원본은 미확인이다.
- Render 워크스페이스 확정, 실제 리소스 생성, Docker 이미지 빌드와 플랫폼 검증,
  실제 프런트 origin 연결은 남아 있다. 로컬 준비안을 실제 배포 완료로 간주하지 않는다.
