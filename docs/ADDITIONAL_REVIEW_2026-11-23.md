# 추가 검토와 원본 보존 ERD

## 추가 발견·수정

`dev/generate_demo_seed.py`의 시연 날짜 계산을 재검토해 다음을 수정했다.

1. 월요일의 과거 진료일은 토요일이다. 기존 `T - 2일` 예약·동의 시각은
   토요일 오후가 되어 오전 진료보다 늦어질 수 있었다. 계정 생성·개인정보 동의·
   과거 예약 시각을 과거 진료일 전날 00:00(KST)로 명시했다.
2. 토요일 시연 시 다음 날 일요일에는 일정이 없어 변경 예약이 생성되지 않았다.
   변경 예약은 일요일을 건너뛴 다음 진료일로 연결한다.
3. 15:00 시연에서는 09:00 예약의 취소가 12:00으로 기록돼 과거 예약을 취소한
   모양이 됐다. 해당 예약의 취소와 새 예약 생성은 당일 08:00으로 맞췄다.

격리된 PostgreSQL 18에서 월~토 6개 날짜와 모든 허용 시연 시각을 조합해
확인했다(6개 사례). 모든 사례에서 예약 8건, 연결된 변경 예약 1건,
일요일 일정 0건, 가입·동의·예약·접수·진료 및 취소 시간 순서를 확인했다.
로컬 생성 SQL도 수정된 생성기로 다시 만들었다. 원격 DB는 변경하지 않았다.

## 남아 있는 반영 항목

- Notion의 DOCTOR 직원 계정 생성·필터·수정, 직원 상세 doctorId, 의사 등록의
  계정 동시 생성, 추가 약품명 응답 설명은 현행 코드에 맞게 갱신이 필요하다.
- 설계 산출물의 수행자 FK 5개는 현행 V2의 account_id 참조와 다르다.
  이는 PostgreSQL 자료형 변환이 아닌 구조 변경이다. 이번 원본 보존 이미지에서는
  사용자 요청에 따라 기존 staff_id 컬럼·관계를 유지했다.
- 수정한 약품명 응답의 운영 반영, 프런트 API 주소/CORS 설정, Render 실제 배포와
  DB 시드 적용은 아직 수행하지 않았다. 배포 전에 실제 대상과 설정을 확인해야 한다.
- 공공데이터는 현재 사전 적재 방식이다. 최신 품목과의 전수 대조나 실시간 동기화가
  요구된다면 별도의 원천 수집·갱신 정책이 필요하며, 기존 데이터 검토와는 범위가 다르다.

## 한영 병기 ERD

`0 프로젝트/12erd.png`와 테이블 정의서를 기준으로 별도 SVG·PNG를 생성했다.
원본 파일은 덮어쓰지 않았다.

- 파일명: `12erd_한영병기_PostgreSQL.svg`, `12erd_한영병기_PostgreSQL.png`
- PNG 크기: 8540 × 7700. SVG는 확대해도 글자·선이 유지되는 벡터 원본이다.
- 원본의 18개 테이블, 116개 컬럼, 27개 FK 관계를 보존했다.
- 한글 이름은 테이블 정의서의 명칭·설명을 사용했다.
- DATETIME → TIMESTAMPTZ, TINYINT → BOOLEAN,
  INT → INTEGER, DECIMAL → NUMERIC로 표기했다.
- DATE·TIME·VARCHAR·BIGINT·SMALLINT는 해당 PostgreSQL 자료형을 유지했다.
- PK/FK와 NOT NULL은 원본 정의서를 따랐다. 실제 SQL 식별자를 한글로 바꾸지 않았다.

이 이미지는 원본 ERD의 한영 병기·PostgreSQL 표기판이다.
현행 V2 DB의 수행자 FK까지 일치시킨 새 설계도로 표시하지 않는다.
