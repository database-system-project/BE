# PostgreSQL 시연 데이터

최신 Notion 재검토 근거는 [검토 결과](NOTION_REVIEW_2026-11-23.md)에 정리했다.
시드는 V2 적용 후 비어 있는 시연 DB를 대상으로 하며 자동 시작 마이그레이션에 포함하지 않는다.

## 준비된 파일

- `dev/local-test-seed.sql`: FE 원본의 계정 6개와 기본정보를 유지한 V2 호환 기본 시드.
- `dev/generate_demo_seed.py`: 기본 시드의 계정·해시를 읽고 시연 시나리오를 추가하는 Python 3.9 이상 생성기.
- `dev/demo-seed.generated.sql`: 2026-11-23 15:00 기준으로 생성한 로컬 SQL.
- `.env.demo`: 이전 단계와의 호환을 위해 둔 로컬 시연 비밀번호 파일. 기본값은 원본과 같은 `Test1234!`이다.

생성된 SQL과 비밀번호 파일은 권한 0600이며 Git에서 제외한다.
계정 비밀번호 해시는 현재 Spring Security PBKDF2 설정과 맞췄다.
원본 아이디·비밀번호·이름·환자 정보를 유지한다. 기본 비밀번호는 전부 `Test1234!`이다.
다른 비밀번호로 생성하려면 `DEMO_PASSWORD` 환경변수를 지정한다.

| 역할 | ID | 이름 |
| --- | --- | --- |
| 관리자 | admin01 | 관리자 |
| 원무 | desk01 | 원무 직원 |
| 수납 | cashier01 | 수납 담당자 |
| 내과 의사 | doctor01 | 이정훈 |
| 피부과 의사 | doctor02 | 김민서 |
| 성인 환자1 | patient01 | 테스트환자 |
| 성인 환자2 (확장) | patient02 | 박서준 |
| 소아 환자 (확장) | patient03 | 김민준 |

이름·전화번호·진료·투약값·예외 사유는 가상 데이터다.
약품·금기 기준은 기존 공공데이터 시드에서 찾는다. 가상 투약값은 실제 복용 안내가 아니다.

## 날짜를 바꿔 생성

BE 폴더에서 다른 이름의 SQL을 생성할 수 있다. 기본 비밀번호 사용에는 별도 설정이 필요 없다.

```sh
python3 dev/generate_demo_seed.py --date 2026-11-24 --time 15:00 --output dev/demo-20261124.generated.sql
```

날짜를 생략하면 한국 시간의 오늘이다. 허용 T는 10:30, 11:00, 11:30, 15:00, 15:30이다.
원본과 같이 일요일은 일정에서 제외한다. 일요일을 시연일로 지정하면 생성기가 중단한다.
T-90분·T-60분의 과거 진료와 T+30분의 예약이 운영시간 안에 있고 점심을 피하도록 제한했다.
이미 있는 출력 파일은 덮어쓰지 않는다. 다른 파일명을 사용한다.
새 비밀번호를 쓰려면 `DEMO_PASSWORD` 환경변수에 8~72자 값을 설정한 뒤 생성한다.

## 적용

먼저 앱을 실행해 Flyway V1·V2·약품 반복 마이그레이션을 적용한다.
생성기 실행은 파일만 만들며 DB에 접속하지 않는다.

기본 계정만 필요하면 `dev/local-test-seed.sql`, 전체 시연 흐름까지 필요하면
`dev/demo-seed.generated.sql` 중 하나를 선택한다. 둘을 연달아 적용하지 않는다.
전체 시연 SQL은 빈 계정 테이블을 요구한다. 기존 데이터에 덧붙이는 초기화 도구가 아니다.

대상 DB를 확인한 뒤 PGHOST·PGPORT·PGDATABASE·PGUSER·PGSSLMODE 등
접속 환경을 설정하고 적용한다. 비밀번호는 터미널 명령 문자열에 직접 넣지 않는다.

```sh
psql -X -v ON_ERROR_STOP=1 -f dev/demo-seed.generated.sql
```

Render의 무료 Web Service에는 셸·일회성 작업 기능이 없다.
Render DB의 내부 접속은 같은 리전 서비스에서만 사용한다.
로컬에서 적용하려면 DB의 외부 접속 주소, TLS, 허용할 클라이언트 IP를 먼저 준비한다.
현재 Blueprint는 외부 DB 접속을 차단하므로 별도 연결 준비 없이 로컬에서 바로 적용되지는 않는다.

SQL은 단일 트랜잭션이며 기존 계정 또는 진찰료가 있으면 중단한다.
DELETE·TRUNCATE·시퀀스 되돌리기를 수행하지 않는다.
한 번 넣은 DB를 자동 초기화하는 기능이 아니며, 반복 실행은 거절된다.
운영 데이터가 섞인 DB에서 사용하지 않는다.

## 시연 흐름

T는 선택한 시연 시작 시각이다. 해당 날짜의 T 근처에 적용하고 시연한다.
T 이전에 적용하면 준비된 진료·접수 중 일부가 현재시각보다 미래일 수 있다.

1. 성인1은 직전 진료일의 초진·결제·30일 처방과 오늘의 재진·미수납·병용금기 예외 이력이 있다.
   환자 화면에서 이력·복약 안내·영수증을 확인한다.
2. 성인2는 오늘 초진 미수납과 대기 진료가 있다. 수납에서 초진 18,000원,
   성인1 재진 15,000원을 비교한다. 의사 대기열에서는 성인2를 진료 시작할 수 있다.
3. 소아는 만 10세이며 오늘 T+30분 예약이다. 원무가 접수한 후 의사가 진료를 시작하고
   기존 연령금기 약품으로 검사해 AGE 경고를 확인한다.
4. 성인2의 대기 진료에서 현재 복용 중인 약과 충돌하는 약품을 검사해 INTERACTION 경고를 확인한다.
5. 성인1에게는 시작시각 전에 취소된 오늘 예약과 `previous_reservation_id`로 연결된
   다음 진료일 예약이 있다. 토요일 시연이면 일요일을 건너뛰어 월요일로 연결한다.
6. 관리자는 진료과·의사·오늘부터 14일의 일정(일요일 제외)·초진/재진 요금·기존 약품 기준을 확인한다.
   시나리오의 과거 이력용으로 직전 진료일 일정도 추가된다.

사용할 약품 ID는 DB의 실제 기준 데이터에서 선택되며 고정 ID를 가정하지 않는다.
병용 예외의 `medicine_id`가 새 후보 약품, `related_medicine_id`가 기존 복용약이다.
소아 과거 처방의 `AGE` 예외에 저장된 `medicine_id`로 새 연령 검사를 할 수 있다.

## 검증 결과

임시 PostgreSQL 18에서 계정 8개·직원 3명·의사 2명·환자 3명·예약 8건·진료 5건·
처방 4건·결제 2건·예외 2건을 확인했다. 전체 계정 로그인, 초진·재진 금액,
대기·접수·진료 시작, 병용·연령 경고, 재실행 거절·데이터 보존을 실제 API와 SQL로 확인했다.
시연 DB는 종료했으며 실제 온케어 서버·Render에는 적용하지 않았다.
